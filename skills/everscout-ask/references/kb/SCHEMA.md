# Schema: beats, notes, reports, the ledger

Everything everscout writes is markdown with flat frontmatter (`key: value`, lists as `[a, b]`), readable in any editor, on GitHub, and as an Obsidian vault. `everscout.py validate`, `lint`, `tally` and `index` read it. Links are relative markdown links, never wikilinks.

## Where things live

```
HOME   ($EVERSCOUT_HOME or ~/.everscout)
  config.json               paths, contact, pace overrides (example: everscout.config.example.json in the repo)
  voice.md                  how the user writes (template: kb/voice-template.md); private
  beats/<slug>/             private beats (shadow built-in ones of the same name)
<repo>/beats/<slug>/        built-in starter beats; <repo>/beats/_template/ is what beat-new copies
DATA   (beats.<slug>.data in config, else data_root/<slug>)
  INDEX.md, HANDOFF.md, log.md, journal.md, feedback.md
  notes/<yyyy-mm>/<id>-<slug>.md   one per thread or page
  reports/<date>-<slug>.md         trend reports (radar)
  study/NN-<slug>.md               the baseline study
  answers/<date>-<slug>.md         questions put to the beat and the answers given (everscout-ask)
  signals/tallies.json, signals.md generated by tally
  stats/series.csv                 metric values, append only (stats collect); stats/export.csv for charts
  reports/charts/                  charts built from the export by chartwright (optional)
  sources/                         dated snapshots: probes, rules pages, watch lists as used
LEDGER (ledger in config, else data_root/_engage)
  engagements.jsonl, INDEX.md      every ask, thank-you and answer, all beats (pacing is per account)
LOCAL  (local_root)
  cache/                           raw feeds and threads, purged after retention_hours (48)
  ratelimit.json, state-<slug>.json, drafts/
```

DATA and LEDGER hold paraphrases and, in the ledger, handles; keep them private (the everlast vault, a private repo, or a local folder). Nothing under DATA, LEDGER or LOCAL belongs in the public repository.

## A beat (`beats/<slug>/`)

| file | holds | parsed by |
|---|---|---|
| `beat.md` | frontmatter settings, then scope, research questions, keep and skip, engagement notes | `Beat.meta` |
| `sources.md` | the watch list: first table with columns `source, kind, group, stance, engage, scan, filter, notes` | `Beat.sources()` |
| `vocab.md` | facets (`## Facet`) of canonical entities (`- id: alias, alias`) | `Beat.vocab()` |
| `questions.md` | seeds under `## Category` headings: `- [tag, tag] question` | `Beat.questions()` |
| `searches.md` | first table `query, cadence, yields`; then pages and "what not to trust" | `Beat.searches()` |
| `study.md` | the baseline study's chapter table and the perspectives to research from | the report skill |
| `metrics.md` | the metrics catalog: first table with the columns below (optional; `beat-check` validates it when present) | `load_metrics()` |

`beat.md` frontmatter keys: `slug, title, status (active|paused|retired), created, verified, engage (true|false), scan_cadence, report_cadence, half_life_days, showcase_words [..], skip_words [..], asked_words [..], mute_words [..], note_sections [..]`. `showcase_words` raise an item's engagement score; `skip_words` exclude it from candidates; `asked_words` extend the phrases that mark a thread as already asked about process; `mute_words` drop items at fetch time; `note_sections` are the body headings of every note.

Stances: `native, open, mixed, hostile, anti, n/a, unknown`. Kinds: see `kb/platforms.md`. Verification markers in `notes`: `✓ YYYY-MM-DD` verified from the rules page or the feed, `~` believed, `?` unknown.

## Metrics (`metrics.md` in the beat, `stats/series.csv` in DATA)

How the skills use them: [stats.md](stats.md). Design and evidence: `ai-docs/research/2026-09-27-beat-statistics.md`.

`metrics.md` columns, in order: `id | question | definition | unit | kind | source | method | cadence | grade | status | version | created | reviewed | archive_reason | headline | approved`. `approved` is optional: a catalog without the column stays valid, and the CLI adds it the next time it saves the table.

| column | values |
|---|---|
| id | lower-case slug, unique in the beat, never reused |
| question | `Q<n>` (a numbered research question in `beat.md`) and a few words |
| definition | one sentence a stranger could recompute from |
| unit | `count`, `share %`, `index`, `rank`, `ratio`, a currency; a unit with share, %, index or rank is averaged over a period, others are summed |
| kind | `leading` or `lagging` |
| source, method | `tally:notes` or `tally:<facet>/<entity>` with `tally`; `gdelt:<query>`, `gdelt-raw:<query>` or `wikipedia:<project>/<Article>` with `api`; `derived:<id> <op> <id>` with `derived`; words naming the release with `manual` |
| cadence | `per scan`, `weekly`, `monthly`, `quarterly`, `on release` |
| grade | Admiralty: source A to F, information 1 to 6 (`B2`) |
| status | `candidate`, `active`, `archived` |
| version | whole number from 1; a change to definition, unit, source or method adds one |
| created, reviewed | ISO dates |
| archive_reason | `stale: ...`, `flat: ...`, `irrelevant`, `gamed`, `superseded-by:<id>`, `source-gone` or free text; required when archived |
| headline | `yes` on at most one metric |
| approved | empty, or the ISO date the user pre-approved promotion (`stats approve`); `collect` and `review` then promote the candidate once it meets the rule |

`stats/series.csv`: header `date,metric,version,value,unit,source,note_ref`, one row per metric per period, appended and never rewritten. `date` is the start of the period the value describes (a Monday for weekly), not the collection time. A failed collection is a row with an empty `value` and `note_ref` = `failed: <reason>`, so gaps stay visible. Archived metrics keep their rows.

## A note (`notes/<yyyy-mm>/<id>-<slug>.md`)

```yaml
---
title: the thread or page title, colons removed
kind: note
status: active
date: 2026-09-26            # when the note was written
verified: 2026-09-26
beat: ai-video
platform: reddit            # reddit, hn, bluesky, mastodon, lemmy, discourse, rss, youtube, github, news, arxiv, huggingface, web
community: aivideo          # subreddit, instance, forum host, feed name
url: https://...            # filled by new-note from the fetched item; never typed from memory
also: [https://...]         # optional: the same story elsewhere
posted: 2026-09-25          # when the source was posted (YYYY-MM-DD)
note_kind: showcase         # showcase, workflow, discussion, release, question, postmortem, analysis, data, news, paper, web
interest: 37                # comment count the source showed (0 when unknown)
top: false                  # appeared in a top-of-week listing
engaged: false              # the user asked or answered in this thread
models: [veo-3.1, kling-3]  # one list per vocab facet, canonical ids only
tools: [comfyui]
tags: [ai-video, reddit]
summary: one line saying what this teaches (shown in the index)
---
```

Body: one `## ` section per `note_sections` entry, then a closing `Related:` line. Default sections: What it is, How it was made, Reception and interest, Why it matters, Questions this raises. Budget 10 to 30 lines. Paraphrase; at most one short quote; say "the maker" or "the poster", never a handle. When an engagement got answers, add `## Their answers` (paraphrased) and set `engaged: true`.

## A report (`reports/<date>-<slug>.md`)

Frontmatter: `title, kind: report, status, date, verified, beat, period: <from>..<to>, notes_read: N, summary, tags: [report]`. Sections in the everscout-report procedure. Links to notes are relative (`../notes/2026-09/...`); external links must be held by a note (`lint`).

## A study chapter (`study/NN-<slug>.md`)

Frontmatter: `title, kind: study, status, date, verified, beat, tags: [study, <topic>], summary`. 80 to 200 lines, a `## Sources` section with dated links, a `Related:` line to neighbouring chapters.

## An answer (`answers/<date>-<slug>.md`)

Frontmatter: `title, kind: answer, status, date, verified, beat, question, grade (enough|partial|none), confidence (high|medium|low), notes_used: N, fresh_sources: M, summary, tags: [answer]`. Sections: Answer, What the beat has seen, What is new, Where sources disagree, Confidence and gaps, Sources, then `Related:`. Follow-ups append `## Follow-up: <question>`. Links to notes are relative (`../notes/...`); external links must be held by a note or the source log (`lint` checks `answers/` like reports). `everscout.py recall` searches answers with the notes, so a question asked again starts from the last answer.

## The ledger (`engagements.jsonl`)

One JSON object per line: `ts, beat, platform, community, item, url, author, title, kind (ask|thanks|answer), questions [..], route (manual|api|browser), status (drafted|handed|posted|dropped), text, text_sha, comment_url, override, replies [{id, when, text, is_op}]`. `handed` means the text was given to the user to paste; it counts for pacing exactly like `posted`. `drafted` and `dropped` do not count. `INDEX.md` is generated.
