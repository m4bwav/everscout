## Active

- 2026-09-28 `record-drafts-at-once` (user correction). The fishing-game ask (r/aigamedev 1ws5zlf) was drafted in one session and left only in the beat's HANDOFF, not the ledger. Mark posted it and got an answer, so `followups` never looked for replies. When he said "I got an answer to the last question", the next session took the newest ledger ask (BLOCKFALL) and was wrong. Two rules: record every draft the moment it is shown (`engage-record --status drafted`) so a later session can flip it to `posted`; and on "I got an answer", read the beat's HANDOFF and the `drafted` entries before assuming the newest `posted` ask. A late record gets its real time: take the user's comment's `published` from `thread --json` and set `ts` to it, or the pace check counts it as just now.
- 2026-09-28 `token-savers-engage` (workaround, user asked to record token-saving processes). Net savers for this skill: `engage-check` first (ends the task before any thread is read); `thread --json` into the scratchpad and print only the user's comment and the few after it (about 350 tokens instead of about 4k for a 126-comment thread); a maker's answer comes from the ledger's `replies[].text` by grep, not a re-fetch; `followups` in the background (it outruns the 120-second foreground timeout). See `ai-docs/solutions/2026-09-28-token-saving-processes.md` for the full list and the proposed CLI additions.
- 2026-09-29 `followups-finds-hand-posted-asks` (failure in use, then fixed). Mark posted the r/aivideo ask (1wsjqpl) by hand, so its ledger entry stayed `drafted` and `followups` never looked at it; after `engage-update --status posted`, the entry's `ts` jumped to the update time, later than the maker's reply, so the reply was still skipped; and once dated right, every later comment by the maker in the thread (18 thanks to other people) counted as a reply, because Reddit feeds carry no parent ids. Fixed in `everscout.py followups`: with `reddit_user` set, a drafted Reddit ask is checked too; the user's own comment in the thread dates the ask (and marks a draft posted with its permalink); replies are read from the subtree under the user's comment permalink only. Result on 1wsjqpl: exactly the 2 real replies. Rule: after a hand-posted ask, just run `followups`; no `engage-update` needed.
